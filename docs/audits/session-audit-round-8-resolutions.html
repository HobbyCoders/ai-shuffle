Implementation update

PR #1192 now contains application fixes and regression tests, not just this report. These changes are not deployed to the installed app by building this branch.

  • F1: Optional compaction commits only worthwhile batches, rolls back rejected state, and waits for reclaimable growth. Context-window protection bypasses the optional guard. Long turns can compact completed call segments while retaining recent segments, tool pairs, original user constraints and typed steering deliveries.
  • F2: Fingerprints include previously omitted content and request settings. Responses also records serialized-wire fingerprints. Partial-miss warnings account for shared-prefix estimates and are limited per turn; they do not establish provider fault or savings.
  • F3: Closing a run settles cancellation, retains observed usage and publishes one terminal. Checkout cleanup waits for requesting-session execution to settle. Unexpected kills remain deliverable, and failed notification enqueue does not spend the delivery latch.
  • F5–F6: Read-only discovery errors are recoverable without weakening execution failures. AST inspection is allowlisted. Runtime facts describe the actual interpreter and missing dependencies; provisioning records a receipt, rejects empty dependency trees and does not silently install packages or download a missing Svelte CLI.
  • F7: Browser navigation waits briefly for hydration and reports zero-ref pages neutrally. Targetless keys retain ownership checks. An opt-in, source-stamped preview runs with a separate profile, database and ports, without weakening forwarded-header authentication or copying credentials.
  • F8: Error previews retain traceback beginnings and endings, with bounded retrieval by record identity. Successful browser long-polls no longer produce misleading slow-request warnings.
  • F9–F11: Monitor drains output before settlement and uses the process exit code, not missing attribution, to classify outcomes. Terminal summaries and report references survive registry restart through additive database columns. Receipts permit disjoint work without polling; shell output is fenced as untrusted data while code-mode parsing retains raw stdout. Failure notes stop presenting successful earlier calls as the explanation for later failures.
  • F12–F13: Display-only account metadata has identity-bound single-flight caching; permission checks remain uncached. Badge polling coalesces requests, pauses when hidden and backs off failures. Memory documentation describes current writers and replication. A local evidence CLI records command exit status, revision/worktree fingerprints, JUnit counts and artifact hashes, and cleans up process trees on timeout.

Original research: delivery order

  2. In parallel: truthful provisioning, supported authenticated branch preview, safe discovery batches, preserved error detail and untrusted shell-output framing.
  3. Then: bounded within-turn digestion, measured prompt/cache policies, shared tool wording, polling/documentation repairs and evidence-bound PR claims.
  4. Last: user-approved prose-skill optimization.

Implement as focused PRs with explicit acceptance tests, not one large “audit fixes” change. Fluid now lives in this monorepo; the old upstream-first/vendor-sync plan is stale. Engine changes need both engine and app integration coverage, using their separate dependency environments.

Corrections to the audit’s numbers and certainty

  • The reported totals imply uncached input was 83.18% of the bill, not the early claim of 75%. The report itself gives 83% later.
  • The quoted token prices and totals imply a 56.49% token-weighted cache-hit rate, consistent with the 56% headline. The current quant_pass.py computes cached/(fresh+cached) from Usage rows. The diagnostic’s 1,024-token gate therefore does not, by itself, make that headline optimistic.
  • The per-session “fair cost” estimates sum to $181.50. They are judgments, not a measured achievable bill. The approximately $155 compaction attribution has not been independently recalculated from original events here and is not guaranteed savings.
  • At the audit’s quoted $10/M fresh and $1/M cached prices, recaching saves $9/M, not $10/M. Removing tokens, recaching tokens and overlapping failure causes need separate accounting.
  • The current script’s “ttft” uses a Usage/completion boundary, not first-token arrival. Its output rate includes the whole measured request interval. Those metrics do not isolate prefill from decoding or prove that the provider is the dominant cause of latency.

The strongest next experiment is a controlled before/after long-turn replay with preserved task outcomes, actual serialized-prefix telemetry and live account usage—not another subjective fair-price estimate.

1. Stop repeated low-value compaction — F1

P1 · Reproduced in current code; historical savings remain estimates.

User interjections are appended inside tool results, so they do not create new digestible turns. The newest three turns stay protected; old arguments and reasoning keep growing while tier 1 trims small amounts before successive model calls.

A read-only reproduction of a 50-call turn produced 19 compaction batches. The final six reclaimed only 457–458 estimated tokens each and left the prompt above the trigger.

Resolution: Evaluate compaction as a transaction over the entire candidate result. Commit useful reductions; otherwise keep the existing prefix and defer another optional attempt until reclaimable content grows. Add completed model-call segments inside long turns, including turns without interjections. Preserve user constraints as typed, persisted data before digesting their enclosing results; preserve tool-call/result pairing and recovery references.

Do not impose an unconditional 5% threshold or per-turn limit: either can prevent essential reclaim near overflow. Separate discretionary compaction from mandatory window protection, including output reserve. Argument stubbing needs separate provider-serialization tests. Report estimated before/after tokens and the earliest changed prefix position.

Evidence: fluid/fluid/context/compaction.py:224; fluid/fluid/context/compaction.py:589; fluid/fluid/engine/native.py:4003

Acceptance: Growing protected-turn replay stops repeated tiny rewrites while headroom remains; near-overflow replay still reclaims safely. Resume/fork retains interjections, tool pairing and original-content references. Include digest expansion and image-state rollback tests.

2. Repair cache diagnostics before blaming the provider — F2

P1 · Partial-miss blind spot reproduced; gateway causation not verified.

The diagnostic returns no miss when cached tokens exceed 1,024. A 150,000-fresh / 20,000-cached reproduction returned no diagnosis. More importantly, current fingerprints omit tool names and raw reasoning, and hash only image length plus its first 64 characters. Changing those omitted fields changed serialized Responses items without changing the fingerprint.

Resolution: Version fingerprints around the actual serialized request content, without logging sensitive payloads. Estimate the reusable shared prefix and compare it with actual cached tokens. Track new suffixes, intentional rewrites, provider/model/settings changes and request intervals separately. Record per-call diagnostics, but aggregate user alerts to avoid recreating warning spam.

A cached/total ratio alone is insufficient: a large new suffix is legitimately uncached. An unchanged current fingerprint is not proof of an unchanged wire prefix. Call the financial metric estimated avoidable cost; use the cached-versus-uncached price difference. Provider mitigation needs a controlled live probe on the configured account, not a claim based on these hashes.

Evidence: fluid/fluid/context/cache_probe.py:179; fluid/fluid/context/cache_probe.py:313; fluid/fluid/providers/openai_responses/serialize.py:134

Acceptance: Detect partial loss of reuse without flagging a genuinely new suffix. Cover tool-name, reasoning and image mutations; resume, aborted streams and provider changes. Only then compare live repeated-prefix requests and costs.

3. Give every cancelled turn a truthful terminal record — F3

P1 · Cancellation gap confirmed; historical close caller remains unknown.

Direct engine closure cancels the active task, whose cancellation branch re-raises without a terminal event carrying observed usage. Pool removal can reach that path. Requesting-session checkout cleanup still removes its own pooled engine; PR #1181 protects other sessions but does not settle this one first. PR #1184 improves desktop quit ordering, not every direct close.

Resolution: Finalize an active turn exactly once with a reason and observed usage/model-call totals before closing the event bus. Preserve cancellation propagation, bound shutdown and make accounting idempotent. Defer checkout cleanup until settlement, or explicitly interrupt and await it. Record the caller and close reason.

The audit overstates the absence of live recovery: a progress watchdog exists, with a default 1,800-second silence budget. It is not an immediate dead-engine detector. A null worktree ID is a lead, not proof of historical causation. Prefer runtime/task liveness and ownership over a simple elapsed-time sweep.

Evidence: fluid/fluid/engine/native.py:1585; fluid/fluid/engine/native.py:1904; app/api/git_operations.py:386; app/core/session_runtime.py:1275

Acceptance: Close during provider streaming and tool execution; test Stop, quit and requesting-session checkout cleanup with a null worktree ID. Require one terminal, observed usage reconciliation, released ownership, no unintended wake and no interruption of another worker.

4. Make background results durable and accurate — F9

P1 · Exit-code race, service-success misclassification and reconciliation data loss confirmed.

The detached watcher can see the process exit before the output reader assigns the task exit code. It then treats a missing code as deliberate cancellation and discards output. Separately, a service that survives its startup grace can later exit nonzero and still be classified as completed. Reconciliation constructs status-only text instead of retaining the original result.

Resolution: Coordinate process exit and output-drain settlement, with a bounded deadline and the authoritative return code. Missing attribution means unknown or incomplete observation, not deliberate Stop. Keep available output. Preserve the same terminal record, summary and output reference across receipt, registry, reconciliation and wake delivery.

Differentiate explicit user/agent stops from unexpected kills. Make notification delivery retryable; do not mark it delivered before enqueue succeeds. Supervise the real foreground process, or use explicit bounded health checks rather than trusting a launcher PID.

The proposed arbitrary pause before parking is not established as necessary. Existing code serializes park/completion decisions; prove duplicate consumption or redundant wakes first. Wake prompts are recorded on current ordinary unpark paths, so the audit/export gap needs separate investigation. A trailing shell command returning 1 is ordinary shell semantics, not a reason to rewrite task status.

Evidence: app/mcp/builtin_tools.py:968; app/core/monitor_spawn.py:1105; app/core/monitor_spawn.py:601; app/core/pending_reconcile.py:185; app/core/turn_scheduler.py:1522

Acceptance: Force exit before output drain, delayed inherited stdout, reader failure, service crash, explicit Stop, unexpected kill, enqueue failure/retry and completion on both sides of park. Require one consumption, consistent status and retained output.

5. Keep exploratory failures recoverable without authorizing edits — F5

P1 · Missing-path batch abort confirmed; some warning text already exists.

Read, Grep and Glob return hard errors for missing paths, which abort the remaining Python cell. This defeats useful independent discovery batching. The current code-mode prompt already says failed/denied calls raise; the audit is wrong that this is entirely undocumented.

Resolution: Support explicitly recoverable read-only discovery batches with error status distinct from returned text. Keep dependent edits gated on successful prerequisites. Permission denials, cancellation and mutation failures must still stop. Do not follow the audit’s suggestion to put mutations first merely to avoid a later read failure. Review adding ast separately with sandbox tests.

Evidence: fluid/fluid/tools/builtins/read.py:164; fluid/fluid/codemode/bridge.py:232; fluid/fluid/cli/prompt.py:918

Acceptance: A missing exploratory read does not block another independent read. A failed prerequisite never becomes valid content or permission to edit. Invalid patterns differ from no matches; completed edits are never replayed.

6. Publish actual environment state — F6

P1 · Reproduced in this checkout, not only the historical audit.

The default Python is the packaged worker interpreter and cannot import pytest. This checkout had no venv, .venv, frontend/node_modules or app/static during the probe, despite the generic provisioning assurance. Provisioning skips absent source dependencies and logs its result without exposing it to the session.

Resolution: Resolve executable paths and dependency state during provisioning, publish a truthful ready/degraded result, and advertise only a verified test invocation. Recall can help with conventions but cannot certify current machine state. Missing dependencies need an explicit setup decision; do not silently execute package lifecycle scripts or mutate shared dependencies. Preserve credential-copy prevention and Windows junction safety.

Evidence: app/core/checkout_manager.py:892; app/core/checkout_manager.py:590; fluid/fluid/context/environment.py:190

Acceptance: Exercise actual fresh-checkout provisioning with absent, current and stale dependencies. The session receives each outcome and can execute the advertised check without credential copying or sibling-checkout damage.

7. Provide a supported authenticated branch preview — F7

P1 · Code-level obstacles confirmed; running preview not exercised.

Vite adds x-forwarded-host, which deliberately disqualifies a request from local-owner authorization. Browser navigation snapshots after DOMContentLoaded without an app-readiness condition. Zero refs are interpreted too strongly, and keyboard actions unnecessarily require a target and can inherit screenshot requirements.

Resolution: Provide a branch-identifiable preview through an explicitly trusted, authenticated route. Do not remove forwarded-header checks, broadly trust hostnames, or disable TLS validation to make testing convenient. Add bounded readiness handling, neutral “no actionable refs yet” diagnostics and targetless keys on the active page while retaining ownership and stale-coordinate protections.

Browser source is in this monorepo, but the configured runtime points to the packaged installation. Source changes alone do not prove the tools in use changed.

Evidence: frontend/vite.config.js:65; app/core/owner_auth.py:74; browser-mcp/src/tools/navigate.ts:94; browser-mcp/src/tools/act.ts:50

Acceptance: Test delayed hydration, real blank failures, canvas/prose content, auth walls and consecutive targetless keys. Then open the changed branch’s actual screen at the affected viewport and confirm the build identity. Negative tests must keep proxy/tunnel access unauthorized.

8. Preserve the useful part of errors — F8

P1 · Final-exception loss reproduced; warning noise is conditional.

The current clipping helper keeps only the traceback head. Executing that helper in isolation confirmed that a final exception beyond 2,000 characters disappears. Cache diagnostics log WARNING, and a successful 20-second browser poll can cross the generic 1.5-second slow-request warning threshold. GetAppErrors already defaults to ERROR+, so warning flooding is not unconditional.

Resolution: Retain traceback head and tail, including final exception and chained causes, with bounded follow-up retrieval by record identity. Separate routine cache telemetry from actionable failures. Exempt successful expected long-polls from generic slow warnings, not failed polls or all browser requests. The clipping helper is shared with GetAppLogs; cover both.

Evidence: app/mcp/builtin_tools.py:191; app/core/browser_control.py:274; app/main.py:415

Acceptance: Exercise logger → error store → tool output with long chained exceptions and ordinary polls. Keep the final exception inside the payload budget and retain genuine WARNING/ERROR failures.

9. Stabilize prompts without freezing permissions — F4

P2 · Partly confirmed; address after compaction and measurement.

Date, branch and memory already ride newer user messages rather than the compiled system prompt. Engine reconnects can still rebuild incidental prompt/catalog content. Image consumption is not strictly turn-boundary-only: overflow and full-result trimming can remove images mid-turn.

Resolution: Persist versioned incidental prompt/catalog inputs across reconnects, with deliberate rebuilds for capability changes. Revocation, computer-use disablement, directory removal and provider changes must take effect immediately. Do not freeze authority-bearing settings until a compaction that might never happen.

A parked session does not prove an expired cache. Cold-wake compaction and image removal should be measured policies, not unconditional rules. Preserve unseen images and necessary visual evidence; including older images in a compaction can move the changed prefix earlier and increase cost.

Evidence: app/core/provider/harness_adapter.py:1267; app/core/session_pool.py:1759; fluid/fluid/context/compaction.py:576

Acceptance: Unchanged reconnects preserve serialized prefixes, while revocations remain immediate. Compare actual cost, latency, overflow and recovery reads before adopting cold-wake or image policies.

10. Correct tool wording at the layer that actually runs — F10

P2 · Useful low-risk cleanup; not a substitute for lifecycle fixes.

Fluid’s Monitor receipt already permits independent work, but the app overrides it with “End the turn now.” The service heuristic matches vite build, and Bash’s timeout response recommends appending & and polling, contradicting its own Monitor guidance.

Resolution: Reuse one consistent receipt across app and engine. Tell agents to inspect failed/truncated results and finish outstanding requested work, without inventing unrelated tasks. Narrow the service heuristic. Clarify Glob’s recursive file-search semantics and distinguish AskUser decisions from reversible defaults and harness permission prompts. The actual AskUser round-trip exists; no broken modal was demonstrated when it is called.

Evidence: app/core/monitor_spawn.py:218; fluid/fluid/tools/builtins/monitor.py:245; fluid/fluid/tools/builtins/bash.py:303

Acceptance: Check actual emitted receipts in inline/background paths. vite build remains a one-shot command. Genuine blocking decisions use the modal, and dismissal, timeout or prose is never treated as approval.

11. Extend untrusted-data handling to shell output — F11

P1 · Framing gap confirmed; no exploit reproduced.

Registry fencing applies to MCP results, while WebFetch/WebSearch fence their own content. Bash output is not equivalently labeled. Existing prompt policy, control-marker defanging and permission gates still provide protections; the audit should not imply there are none.

Resolution: Treat shell stdout/stderr as data at the model boundary, with trusted exit-status metadata kept separate. Preserve provenance through code-mode results, truncation, errors and background output. A regex for gh/curl/wget is only a partial fix: wrappers, pipes, scripts and downloaded files bypass that classification. Fences are a model-facing defense, not proof that prompt injection is solved. External instructions must never authorize a write or relax an existing permission decision.

Evidence: fluid/fluid/tools/registry.py:532; fluid/fluid/tools/builtins/bash.py:323; fluid/fluid/tools/hardening.py:56; fluid/fluid/engine/native.py:3952

Acceptance: Cover direct and wrapped fetches, pipelines, errors, background output, replay and forged closing/control markers. Remote content must not become a trusted user request or bypass write permissions.

No personal instruction was changed in this review.

But the cited 30/minute limiter applies to link/enroll, not account GET; checked-in hub code applies a global 120/minute/source-IP limit. No new incident was reproduced. Keep browser observations separate from unit tests, reject stale/failed/missing evidence, and cover direct gh workflows rather than only the app’s PR API. Avoid privileged CI execution of untrusted PR content.
